# Salamander в Rider (и других IDE JetBrains)

Полная поддержка `.sal` в Rider: ошибки на лету, автодополнение (Engine, API
игры, события — с сигнатурами и доками из `salamander-api.json`), hover,
переход к определению, символы. Работает через LSP — тот же сервер, что и в
VS Code, тот же компилятор, что в игре.

## Шаг 1. Собрать LSP-сервер (один раз)

Из корня репозитория (нужен .NET SDK 8):

```bash
dotnet publish Tools/DslLsp -c Release -o Tools/DslLsp/publish
```

Появится `Tools/DslLsp/publish/DslLsp.dll`. После обновления движка — просто
повторите команду.

## Шаг 2. Установить LSP4IJ

Settings → Plugins → Marketplace → **LSP4IJ** (открытый LSP-клиент от Red Hat
для IDE JetBrains) → Install → перезапуск IDE.

## Шаг 3. Подключить сервер

Откройте панель **LSP4IJ** (View → Tool Windows → LSP4IJ или через Settings →
Languages & Frameworks → LSP4IJ) → **New Language Server** → шаблон
«User-defined»:

- **Name**: `Salamander`
- **Command** (путь с пробелами — ОБЯЗАТЕЛЬНО в кавычках):
  `dotnet "C:\путь к репозиторию\Tools\DslLsp\publish\DslLsp.dll"`
- **Mappings** → File name patterns: `*.sal` (язык можно указать как
  `salamander` или оставить TextMate).

Сохраните. Сервер берёт корень воркспейса из IDE и ищет под ним модули (папки
с `module.json`, вглубь, мимо `Library/`, `Temp/`, `obj/`, `.git/`) и
`salamander-api.json` (сначала в корне, потом ближайший в подпапках). Для
папки с модами этого достаточно — ошибки появятся в редакторе и в панели
Problems.

### Если открыт весь Unity-проект

Тогда корень — корень проекта, а модули лежат где-то в
`Assets/StreamingAssets/...`. Автопоиск их найдёт, но честнее и быстрее
указать явно: в настройках сервера LSP4IJ есть вкладка **Configuration →
Initialization Options** (JSON, уходит в `initialize`):

```json
{
  "salamander.modulesRoot": "Assets/StreamingAssets/Core",
  "salamander.apiManifest": "Assets/StreamingAssets/Core/salamander-api.json"
}
```

Пути — абсолютные либо относительно корня воркспейса. Понимаются три ключа:

| ключ | что делает |
|------|------------|
| `salamander.modulesRoot` | папка, под которой искать модули и `*.sal`; по умолчанию — корень воркспейса |
| `salamander.apiManifest` | точный путь к манифесту API игры |
| `salamander.buildFile` | точный путь к `salamander-build.json`; пути внутри него — относительно его же папки |

Проверить, что применилось: панель LSP4IJ → сервер Salamander → вкладка
**Logs**. При старте сервер печатает корень воркспейса, каждую заданную
настройку и предупреждение, если модулей не нашлось.

## Шаг 4. Ассоциация расширения `.sal` (обязательно)

При первом открытии `.sal` Rider покажет окно **Register New File Type
Association** («The file ... is not associated with any file type»). Выберите
**первый** вариант — «Open matching files as text and auto-detect file type by
content» — и OK.

Это не косметика. Без ассоциации файл остаётся с типом *unknown*, а у такого
типа **уровень подсветки выключен**: редактор покажет голый текст, а в правом
верхнем углу будет `OFF`. Причём выключено оно per-file, так что иначе пришлось
бы включать вручную на каждом файле. С текстовым типом уровень включён по
умолчанию во всех проектах, и сервер красит поверх.

Если окно уже было закрыто «не тем» выбором: Settings → Editor → **File Types**
→ найдите тип, в чьи «File name patterns» попал `*.sal`, и уберите его оттуда,
затем откройте `.sal` заново.

## Шаг 5. TextMate-бандл (опционально)

Весь цвет и так даёт LSP-сервер: он отдаёт семантические токены на ключевые
слова, типы, вызовы, свойства, элементы енумов, строки, числа и комментарии.
Бандл TextMate добавляет к этому подсветку, не зависящую от компиляции —
она работает мгновенно при наборе и в файлах с синтаксическими ошибками:

Settings → Editor → **TextMate Bundles** → «+» → папка
`Tools/vscode-salamander` из репозитория → Apply → перезапуск IDE.

**Оговорка по опыту:** на Rider бандл может подключиться (и отображаться в
списке включённым), но так и не перехватить расширение `.sal` — тогда
подсветка целиком остаётся за сервером, и это рабочее состояние, а не поломка.
Проверяется одним движением: остановите сервер Salamander в панели LSP
Consoles и посмотрите на открытый `.sal`. Цвет остался — работает грамматика;
цвет пропал — красит только сервер. В VS Code бандл используется всегда.

## Обновление сервера

После обновления движка повторите `dotnet publish` из шага 1 и перезапустите
сервер в LSP4IJ (или IDE). Новые возможности (семантическая подсветка,
подсказка сигнатур, сниппеты аргументов) подхватятся автоматически.

Если сборщик вашего проекта экспортирует `salamander-build.json` (в корень
модулей или туда, куда указывает `salamander.buildFile`) — сервер компилирует
РОВНО перечисленные там модули в заданном порядке; без него — обходит дерево
(дев-режим). Пути внутри build-файла считаются от папки самого файла, так что
его можно положить и в корень Unity-проекта:

```json
{ "modules": ["Assets/StreamingAssets/Core/core.weapons"] }
```

## Если что-то не так

- **`JsonRpcException: Stream Closed`** — сервер умер сразу после запуска,
  IDE пишет initialize в закрытую трубу. Почти всегда это команда:
  1) путь к dll содержит пробел и не взят в кавычки (`Salamander DSL` →
     dotnet получает два обрезка пути); 2) dll не существует по указанному
     пути (не выполнен шаг 1); 3) рядом с dll нет `DslLsp.runtimeconfig.json`
     (копировали одну dll вместо всей папки publish). Выполните команду руками
     в терминале: живой сервер напечатает
     `salamander-lsp: запущен, жду initialize по stdio` и будет молча ждать —
     если вместо этого ошибка dotnet, причина перед вами.

- **«Нет подсветки, в правом верхнем углу редактора `OFF`»** — у `.sal` нет
  ассоциации с типом файла, см. шаг 4. Разово помогает переключить виджет на
  **All Problems**, но уровень запоминается НА ФАЙЛ
  (`.idea/workspace.xml`, `HighlightingSettingsPerFile`), поэтому жать
  пришлось бы на каждом. Лечится ассоциацией расширения — один раз и на все
  проекты.

- **«Ошибок нет вообще, автодополнение по API игры не работает»** — сервер не
  нашёл модули или манифест. Откройте вкладку **Logs**: там видно, какой корень
  он взял, и есть ли строка «модулей не найдено под ...». Лечится настройками
  `salamander.modulesRoot` / `salamander.apiManifest` выше. Манифест игра
  экспортирует сама при запуске в редакторе; без него сервер честно
  предупредит прямо в Problems (W0401).
- Сервер не стартует — выполните команду из шага 3 руками в терминале: живой
  сервер молча ждёт ввода (это норма), ошибки .NET будут видны сразу.
- Логи LSP4IJ: панель LSP4IJ → вкладка соответствующего сервера.
