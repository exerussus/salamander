# Salamander в Rider

Полная поддержка `.sal` в Rider:
- ошибки на лету;
- автодополнение: Engine, API игры, события — с сигнатурами и доками из `salamander-api.json`;
- hover, переход к определению, символы;
- подсветка и шаблоны.

Всё это работает через LSP — тот же сервер, что и в VS Code, и тот же компилятор, что в игре.

## Установка (две минуты)

1. **LSP4IJ.** Settings → Plugins → Marketplace → **LSP4IJ** (Red Hat) → Install.
2. **Плагин Salamander.** Соберите его один раз: `Tools/rider/plugin/build.sh`
   (нужны Rider, LSP4IJ и .NET SDK 8 — всё ищется само). Потом Settings → Plugins
   → ⚙ → **Install Plugin from Disk…** → `Tools/rider/plugin/build/Salamander-<версия>.zip`.
3. Перезапустите Rider.

На машине должен быть **dotnet** (.NET 8 Runtime или SDK): им запускается сервер.
Если его нет, плагин скажет об этом уведомлением со ссылкой на загрузку.

## Что плагин делает сам

Раньше всё это настраивалось руками.

| | |
|---|---|
| **LSP-сервер** | Сервер Salamander уже объявлен для LSP4IJ и едет внутри плагина: `dotnet publish`, путь к dll, кавычки и маска `*.sal` больше не нужны. |
| **Unity-проект** | Манифест `salamander-api.json` ищется в `Assets/StreamingAssets`. Его папка становится корнем модулей, JSON в Initialization Options писать не нужно. |
| **Паки в формате игры** | Если `module.json` у игры свой (ключ `scripts`, маски), сервер берёт паки из `Library/Salamander/salamander-build.json` — редактор игры выгружает туда паки уже разобранными и переписывает файл сам при каждой правке `.sal` и `module.json`. Без этого файла сервер видит такие паки пустыми, и ошибок не бывает вовсе. |
| **Тип файла `.sal`** | `.sal` открывается с грамматикой Salamander через TextMate. Подсветка работает сразу, даже при синтаксических ошибках, есть Ctrl+/ и парные скобки. Без TextMate файл открывается как текст. Окна «Register New File Type Association» и `OFF` в углу редактора больше не будет. |
| **Грамматика TextMate** | Встроена в плагин — та же, что у VS Code. В TextMate Bundles ничего добавлять не нужно. |
| **Новый файл** | В проводнике: правый клик по папке → **Add → Salamander File** (в Project view — New → Salamander File). Подробнее ниже. |
| **Шаблоны (live templates)** | `trigger`, `disabled`, `event`, `before`, `after`, `replace`, `action`, `func`, `class`, `enum`, `listener`, `arch`, `if`, `while`, `for`, `foreach`, `wait`, `waituntil`, `spawn` — набрать и Tab. Те же, что сниппеты VS Code. Список — Settings → Editor → Live Templates → Salamander. |
| **Значок `.sal`** | Саламандра в дереве, во вкладках и в поиске. |

### Add → Salamander File

Меню собирается из манифеста API игры — ближайшего вверх от папки, а если такого нет, то манифеста проекта.

В меню два набора пунктов:
- **язык:** Trigger, Listener, Class, Enum;
- **архетипы игры:** все виды, которые объявила игра (`imprint`, `skill`, `item`, `spell`, …). Новый вид появится в меню сам, как только игра выгрузит манифест.

В диалоге:
- вводите id (он же имя файла);
- галочками отмечаете константы и события;
- обязательные константы отмечены заранее и не снимаются;
- значения берутся из дефолтов манифеста, у енумов подставляется законный член;
- в подсказке к каждой строке — дока из манифеста.

Файл создаётся с переводами строк как у соседних `.sal` и открывается с курсором в теле первого события.

Для триггера и подписки в списке событий — события хоста.

## Настройки проекта (если автоматики мало)

Файл `salamander-lsp.json` в корне проекта. Если он есть, сервер получает ровно его, без автоугадывания:

```json
{
  "salamander.modulesRoot": "Assets/StreamingAssets/Core",
  "salamander.apiManifest": "Assets/StreamingAssets/Core/salamander-api.json"
}
```

| ключ | что делает |
|------|------------|
| `salamander.modulesRoot` | папка, под которой искать модули и `*.sal`; по умолчанию — корень проекта |
| `salamander.apiManifest` | точный путь к манифесту API игры |
| `salamander.buildFile` | точный путь к `salamander-build.json`; пути внутри него — относительно его же папки |
| `salamander.referencePaths` | список папок со **справочными модулями** — массив строк (или одна строка, пути через `;`) |
| `salamander.server.path` | свой `DslLsp.dll` вместо встроенного (настройка клиента, серверу не уходит) |

Пути — абсолютные либо относительно корня проекта.

Какой сервер запускается, если `salamander.server.path` не задан:
1. переменная окружения `SALAMANDER_LSP_DLL`;
2. если открыт сам репозиторий Salamander — `Tools/DslLsp/publish/DslLsp.dll`;
3. иначе — сервер из плагина.

### Если открыт мод, а не игра

Справочные модули — то, что видит игра, но чего нет в открытой папке: базовые скрипты игры и зависимости мода.

Без них сервер честно ругается «модуль 'mod' зависит от 'base', который не загружен» и ничего не проверяет. Укажите, где лежат модули игры:

```json
{
  "salamander.apiManifest": "C:/Games/MyGame/Assets/StreamingAssets/Scripts/salamander-api.json",
  "salamander.referencePaths": ["C:/Games/MyGame/Assets/StreamingAssets/Scripts"]
}
```

Что дают справочные модули:
- классы игры есть в автодополнении — поля с типами, методы с сигнатурами и описаниями из `///`;
- они же есть в hover и в подсказке параметров;
- Ctrl+клик ведёт в файл игры.

Их собственные ошибки не показываются. Берутся только те модули, от которых мод зависит (по `dependencies` в `module.json`, по цепочке).

## Переезд со старой ручной настройки

Плагин сам находит ручной сервер LSP4IJ для `.sal` и предлагает удалить его кнопкой в уведомлении. Иначе ошибки и подсказки будут двоиться.

Ручную ассоциацию `*.sal` с текстом он тоже снимает сам: пока она есть, TextMate файл не получит.

Одно придётся убрать руками — бандл TextMate, если вы добавляли `Tools/vscode-salamander` в Settings → Editor → TextMate Bundles. Грамматика теперь приходит из плагина.

Если после установки в Settings → Plugins видны оба плагина — старый «Salamander File Icon» и новый «Salamander», — удалите старый.

## Обновление

После обновления движка пересоберите плагин (`build.sh`), поставьте zip поверх и перезапустите Rider: сервер едет внутри плагина.

Если вы разрабатываете сам движок и открыли его репозиторий, пересоберите сервер: `dotnet publish Tools/DslLsp -c Release -o Tools/DslLsp/publish`. Плагин сам берёт эту сборку, достаточно перезапустить сервер в LSP4IJ.

## Если что-то не так

- **Проверить, что сервер поднялся:** панель LSP4IJ (View → Tool Windows → LSP4IJ) → Salamander → вкладка **Logs**.
  - При старте сервер печатает корень воркспейса, каждую заданную настройку и предупреждение, если модулей или манифеста не нашлось.
  - Командную строку запуска плагин пишет в `idea.log`: Help → Show Log, строка `salamander-lsp:`.
- **`JsonRpcException: Stream Closed`** — сервер умер сразу после запуска. Выполните команду из `idea.log` руками в терминале.
  - Живой сервер напечатает `salamander-lsp: запущен, жду initialize по stdio` и будет молча ждать.
  - Если вместо этого ошибка dotnet, причина перед вами. Чаще всего нет .NET 8 или битый путь в `salamander.server.path`.
- **«Ошибок нет вообще, автодополнение по API игры не работает»** — сервер не нашёл модули или манифест, или видит паки пустыми. Смотрите **Logs** и панель Problems:
  - W0300 «модуль не содержит ни одного исходника» на каждом паке — `module.json` у игры не в апстримном формате, а `Library/Salamander/salamander-build.json` нет или он устарел. Откройте проект в Unity: редактор выгрузит файл сам (руками — Tools → Salamander → Выгрузить build-файл);
  - там видно, какой корень он взял, и есть ли строка «модулей не найдено под …»;
  - лечится файлом `salamander-lsp.json` (см. выше);
  - манифест игра экспортирует сама при запуске в редакторе, а без него сервер предупредит прямо в Problems (W0401);
  - если папки модулей нет по указанному пути, будет W0402 с этим путём.
- **Нет подсветки, в углу редактора `OFF`** — у `.sal` чужой тип файла.
  - Settings → Editor → **File Types** → найдите тип, в чьи «File name patterns» попал `*.sal`, и уберите его оттуда.
  - Плагин поставит правильный тип при следующем запуске.
  - Сам он чужой тип не трогает, только пишет об этом в `idea.log`.
- **Нет пункта Add → Salamander File** — в папке и выше нет `salamander-api.json`, а в корне проекта нет `salamander-lsp.json`. Пункт виден только там, где есть Salamander.

## Без плагина (ручная настройка)

Если плагин не подходит (другая IDE JetBrains, нет возможности собрать), всё то же делается руками:

1. `dotnet publish Tools/DslLsp -c Release -o Tools/DslLsp/publish`.
2. LSP4IJ → **New Language Server** → «User-defined»:
   - **Command:** `dotnet "C:\путь к репозиторию\Tools\DslLsp\publish\DslLsp.dll"` (путь с пробелами — в кавычках);
   - **Mappings:** File name patterns `*.sal`;
   - настройки из таблицы выше — в **Configuration → Initialization Options**.
3. При первом открытии `.sal` в окне «Register New File Type Association» выберите «Open matching files as text» — иначе подсветка `OFF`.
4. По желанию: Settings → Editor → TextMate Bundles → «+» → `Tools/vscode-salamander`.
   - В Rider бандл часто не перехватывает `.sal`, если тот уже связан с текстом (шаг 3).
   - Тогда весь цвет даёт сервер, и это рабочее состояние.
