# Salamander в VS Code

Подсветка синтаксиса, ошибки компиляции на лету, автодополнение (Engine, API
игры, события — с сигнатурами), hover, переход к определению, символы. Всё
умное живёт в LSP-сервере `Tools/DslLsp` — том же компиляторе, что в игре;
расширение только запускает его и показывает результат.

## Шаг 1. Собрать LSP-сервер (один раз)

Из корня репозитория (нужен .NET SDK 8):

```bash
dotnet publish Tools/DslLsp -c Release -o Tools/DslLsp/publish
```

Появится `Tools/DslLsp/publish/DslLsp.dll`. После обновления движка — просто
повторите команду.

## Шаг 2. Установить расширение

```bash
cd Tools/vscode-salamander
npm install
npm run compile
```

Дальше два варианта:

- **Отладка:** открыть эту папку в VS Code → F5 (Extension Development Host);
- **Постоянная установка:** `npx @vscode/vsce package` → затем либо
  «Extensions → … → Install from VSIX», либо
  `code --install-extension salamander-0.1.1.vsix` (подставьте текущую версию).

Собранный `.vsix` лежит рядом, в этой же папке. После правок расширения его
нужно пересобрать и поставить заново — VS Code запускает установленную копию,
а не исходники.

## Шаг 3. Путь к серверу

Если открыт сам репозиторий Salamander — ничего указывать не нужно:
расширение само находит `Tools/DslLsp/publish/DslLsp.dll` (затем `bin/Release`,
`bin/Debug`). Если открыт другой проект (например, Unity-проект игры) — укажите
путь явно: `Ctrl+,` → `salamander` → **Server: Path**:

```
C:\Exerussus\Programs\SalamanderDSL\Tools\DslLsp\publish\DslLsp.dll
```

Путь может вести куда угодно, в том числе за пределы открытой папки. Что важно:

- нужен **`.dll`**, а не `DslLsp.exe` рядом с ним: клиент запускает
  `dotnet <путь>`;
- нужен **.NET 8 runtime в PATH** — проверьте `dotnet --list-runtimes`;
- путь **абсолютный** либо относительно корня воркспейса; понимается
  `${workspaceFolder}`;
- **никакого ведущего слэша** перед буквой диска. `\C:\...` и `/c:/...`
  Проводник Windows открывает, а файловая система — нет: ведущий слэш означает
  корень текущего диска, и `C:` становится именем папки с двоеточием. Свежие
  версии расширения и сервера такой путь исправляют сами, но лучше писать
  сразу верно;
- после правки этой настройки — **`Developer: Reload Window`**: процесс сервера
  запускается один раз при активации расширения. Расширение об этом напомнит.

Настройку удобно держать в **User**-настройках (один сервер на все проекты), а
настройки модулей ниже — в `<проект>/.vscode/settings.json`, потому что они у
каждого проекта свои.

## Шаг 4. Где искать модули (для Unity-проекта)

Открытый Unity-проект — это корень со всем содержимым, а модули лежат где-то в
`Assets/StreamingAssets/...`. Автопоиск их найдёт, но честнее и быстрее указать
явно:

```json
{
  "salamander.modulesRoot": "Assets/StreamingAssets/Core",
  "salamander.apiManifest": "Assets/StreamingAssets/Core/salamander-api.json"
}
```

| настройка | что делает |
|-----------|------------|
| `salamander.modulesRoot` | папка, под которой искать модули (`module.json`) и `*.sal`; по умолчанию — корень воркспейса |
| `salamander.apiManifest` | точный путь к манифесту API игры |
| `salamander.buildFile` | точный путь к `salamander-build.json`; пути внутри него — относительно его же папки |
| `salamander.server.path` | путь к `DslLsp.dll` (см. шаг 3) |

Эти три пути применяются без перезагрузки окна. Если сборщик проекта
экспортирует `salamander-build.json` — сервер компилирует РОВНО перечисленные
там модули в заданном порядке; без него обходит дерево (дев-режим), мимо
`Library/`, `Temp/`, `obj/`, `.git/`.

## Автодополнение API игры

Расширение читает `salamander-api.json` — манифест всего, что игра открыла
скриптам (енумы, классы со свойствами, API-методы, события). Игра выгружает его
сама: запустите сцену в редакторе Unity один раз — файл появится рядом с
модулями (`StreamingAssets/<моды>/salamander-api.json`).

Что даёт манифест:

- `Engine.` → встроенные методы движка с сигнатурами;
- `UnitApi.` / любой API-класс → его методы со сниппетами аргументов;
- `Team.` / любой енум → элементы;
- `event ` внутри триггера → полные сигнатуры хостовых событий (вставляется
  готовый обработчик с параметрами);
- hover по методам API и событиям — сигнатура.

Без манифеста работают подсветка, сниппеты, имена триггеров/классов/функций из
`.sal` воркспейса и все ошибки, не зависящие от API хоста.

## Проверка, что всё поднялось

Откройте любой `.sal` → панель **Output** → в списке каналов справа выберите
**Salamander LSP**. При старте сервер печатает:

```
salamander-lsp: запущен, жду initialize по stdio
salamander-lsp: корень воркспейса: ...
salamander-lsp: modulesRoot = ...
```

Ошибки скриптов появятся в самих файлах и в панели **Problems**.

## Если что-то не так

- **«LSP-сервер не найден»** — не выполнен шаг 1, либо открыт не тот проект и
  не задан `salamander.server.path`.

- **«по пути из настройки salamander.server.path файла нет»** — путь указан, но
  по нему ничего нет; в сообщении видно, во что он развернулся. Обычно это
  ведущий слэш перед буквой диска, `.exe` вместо `.dll` или неверная папка.
  Расширение в этом случае НЕ подставляет другой сервер молча.

- **Сервер не стартует, в Output тишина** — выполните команду руками в
  терминале: `dotnet "<путь к DslLsp.dll>"`. Живой сервер напечатает
  `salamander-lsp: запущен, жду initialize по stdio` и будет молча ждать. Если
  вместо этого ошибка .NET — причина перед вами. Частые: нет .NET 8 runtime;
  скопировали одну dll вместо всей папки `publish` (рядом должны лежать
  `DslLsp.runtimeconfig.json` и `Newtonsoft.Json.dll`).

- **В Problems только «salamander-api.json не найден» (W0401)** — игру в
  редакторе ещё не запускали, манифест не экспортирован. Подсветка и часть
  диагностики работают и без него.

- **В Problems «Папка модулей не найдена» (W0402)** — путь из
  `salamander.modulesRoot` не существует; он приведён в сообщении, сверьте его с
  диском. Ни один `.sal` при этом не проиндексирован, поэтому ошибок по
  скриптам не будет вообще.

- **Ошибок нет и автодополнения по API нет, хотя файлы открываются** — почти
  всегда сервер смотрит не туда: проверьте `modulesRoot` в логе канала
  **Salamander LSP**.
